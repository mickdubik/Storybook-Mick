## Principles

1. **The Signal Rule.** The accent (`--signal`) marks a measured result or an interactive state. Nothing else, and never a large fill.
2. **Outcome first.** The figure leads, process follows. Figures come only from the owner's confirmed facts.
3. **Hairlines, not boxes.** Sections divide by ruled lines. Inset surfaces step one tone off the page (`--paper-2`). No card shadows.
4. **Concentric corners.** Inner radius = outer radius minus the gap between them.
5. **Transform and opacity only.** Nothing animates width, height, padding or margin. Reduced motion shows the same end states instantly.
6. **Honest drawings.** Glyphs draw real values. Diagrams are titled and say they are illustrative.

## The three token tiers

Tokens are written as CSS custom properties in `src/styles/global.css`. Edit them there, never the pages. Three tiers, from raw to specific:

1. **Global.** Raw scales with no role: the fluid type steps (`--t-h1`, `--t-body`, `--t-label`), the spacing scale (`--gutter`, `--section`, `--space-block`, `--space-group`), the radius, the duration and easing (`--dur`, `--ease-out`) and the two font families. Components may use these directly.
2. **Semantic.** Roles that say what a colour is for: `--paper` and `--paper-2` for surfaces, `--ink`, `--ink-2` and `--ink-3` for text, `--rule` for hairlines, `--signal` for a result or an interactive state. Components use these and only these for colour. Theming means redefining this tier: light is the default, dark overrides the same names, so a component never knows which theme it is in.
3. **Component.** Tokens that belong to one component. Where they take a colour they point back to the semantic tier (`--btn-bg: var(--ink)`): the button's `--btn-r`, `--btn-inset`, `--tile`, `--btn-bg`, `--btn-fg` and `--btn-glyph`, and the media frame's `--frame-pad` and `--frame-radius`. A variant sets these on one class instead of restyling the parts.

Why layers? `--paper` tells you what a surface is for, so it survives a re-skin. `#ffffff` tells you only what it looks like.

Two gaps, so the tiers are not oversold. Colour has no separate raw ramp: the hex values sit directly on the semantic names, so tier 1 holds scales but no palette. And the tokens are CSS only, with no JSON source that maps to Figma variables.

## Tokens

All tokens live in `src/styles/global.css`. Never hard-code a colour. Light and dark are both defined: the site follows the system preference unless the header toggle sets `data-theme`. Use the **Theme** switch in the Storybook toolbar to flip it here.

- [Colour](?path=/story/foundations-colour--tokens): paper, ink, rule and signal, with light and dark values and contrast.
- [Typography](?path=/story/foundations-typography--tokens): one family, Geist Variable, plus Geist Mono for meta labels. No serif, no italics.
- [Space and shape](?path=/story/foundations-space-and-shape--tokens): gutters, section and block spacing, frame padding and radii.
- [Motion](?path=/story/foundations-motion--tokens): duration and easing tokens.
- [Layout](?path=/story/foundations-layout--sheet): the page wrapper and the 12-column sheet with its rail and body.

## Components

- [**Button**](?path=/docs/components-button--docs): Primary, secondary and ghost links in medium (52px) and small (44px). Pick the size from the container, not the importance of the action. Add an icon only when it carries meaning: arrow = go to, ↗ = leaves the site, ↓ = scrolls down.
- [**ButtonStates**](?path=/docs/components-buttonstates--docs): A looping demo of the Unbounce design system's primary button states.
- [**Glyph**](?path=/docs/components-glyph--docs): A small honest drawing of one metric: gain, reduction, share, score or multiple. Labels are HTML, never SVG text.
- [**Shot**](?path=/docs/components-shot--docs): The one frame for every product image. Transparent images sit on the canvas as a single frame, never a frame inside a frame.
- [**Plate**](?path=/docs/components-plate--docs): An illustrative SVG diagram, at most one per case: traffic, tokens, portal or care.
- [**Availability**](?path=/docs/components-availability--docs): The line that says Mick is open to new projects ("Open to new projects in 2027"). The year ticks over like an odometer the first time it scrolls into view. The text comes from `availability` in `src/data/site.ts`.
- **Demos**: Animated case covers: [Smart Traffic](?path=/story/demos-smarttraffic--framed), [DocPortal](?path=/story/demos-docportal--framed) and [Doctor Online](?path=/story/demos-doctoronline--framed). They play on screen only, and reduced motion shows a still.

## Run it

Node 22. From the `Core/` folder:

```bash
npm run storybook        # dev server on port 6006
npm run build-storybook  # static build into storybook-static/
npm run build            # the site build, the only automated check
```

Every command and check is listed on the [Toolkit](?path=/docs/toolkit--docs) page.

Stories use the community Astro framework (`@storybook-astro/framework`), because Storybook has no official Astro support.
