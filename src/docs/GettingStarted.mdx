## Principles

1. **The Signal Rule.** The accent (`--color-accent`) marks a measured result or an interactive state. Nothing else, and never a large fill.
2. **Outcome first.** The figure leads, process follows. Figures come only from the owner's confirmed facts.
3. **Hairlines, not boxes.** Sections divide by ruled lines. Inset surfaces step one tone off the page (`--color-background-subtle`). No card shadows.
4. **Concentric corners.** Inner radius = outer radius minus the gap between them.
5. **Transform and opacity only.** Nothing animates width, height, padding or margin. Reduced motion shows the same end states instantly.
6. **Honest drawings.** Glyphs draw real values. Diagrams are titled and say they are illustrative.

## The three token tiers

Tokens are written as CSS custom properties in `src/styles/global.css`. Edit them there, never the pages. Three tiers, from raw to specific:

1. **Global.** Raw scales with no role: the fluid type steps (`--font-size-h1`, `--font-size-body`, `--font-size-label`), the spacing scale (`--space-gutter`, `--space-section`, `--space-block`, `--space-group`), the radius, the duration and easing (`--duration-default`, `--easing-out`) and the two font families. Components may use these directly.
2. **Semantic.** Roles that say what a colour is for: `--color-background-default` and `--color-background-subtle` for surfaces, `--color-text-default`, `--color-text-secondary` and `--color-text-muted` for text, `--color-border-default` for hairlines, `--color-accent` for a result or an interactive state. Components use these and only these for colour. Theming means redefining this tier: light is the default, dark overrides the same names, so a component never knows which theme it is in.
3. **Component.** Tokens that belong to one component. Where they take a colour they point back to the semantic tier (`--btn-background: var(--color-text-default)`): the button's `--btn-radius`, `--btn-inset`, `--btn-tile-size`, `--btn-background`, `--btn-text` and `--btn-glyph-color`, and the media frame's `--frame-padding` and `--frame-radius`. A variant sets these on one class instead of restyling the parts.

Why layers? `--color-background-default` tells you what a surface is for, so it survives a re-skin. `#ffffff` tells you only what it looks like.

Two gaps, so the tiers are not oversold. Colour has no raw palette in the CSS: the semantic names point straight at hex values, so tier 1 holds scales but no colours. The Primitives page names the raw colours (`neutral-300`), but only in Storybook. And the tokens are CSS only, with no JSON source that maps to Figma variables.

## Tokens

All tokens live in `src/styles/global.css`. Never hard-code a colour. Light and dark are both defined: the site follows the system preference unless the header toggle sets `data-theme`. Use the **Theme** switch in the Storybook toolbar to flip it here.

- [Tokens](?path=/story/foundations-tokens--reference): every token in one list, by tier: global, semantic and component.
- [Colour](?path=/story/foundations-colour--semantic): the semantic roles (surfaces, text, lines, signal) with light and dark values and contrast, plus the [primitives](?path=/story/foundations-colour--primitives) behind them.
- [Typography](?path=/story/foundations-typography--scales): one family, Geist Variable, plus Geist Mono for meta labels. No serif, no italics.
- [Space and shape](?path=/story/foundations-space-and-shape--space-and-shape): gutters, section and block spacing, frame padding and radii.
- [Motion](?path=/story/foundations-motion--durations): duration and easing tokens.
- [Layout](?path=/story/foundations-layout--sheet): the page wrapper and the 12-column sheet with its rail and body.

## Components

- [**Button**](?path=/docs/components-button-variants--docs): Primary, secondary and ghost links in medium (52px) and small (44px). Pick the size from the container, not the importance of the action. Add an icon only when it carries meaning: arrow = go to, ↗ = leaves the site, ↓ = scrolls down.
- [**ButtonStates**](?path=/docs/components-button-states-demo--docs): A looping demo of the Unbounce design system's primary button states.
- [**Glyph**](?path=/docs/components-graphics-glyph--docs): A small honest drawing of one metric: gain, reduction, share, score or multiple. Labels are HTML, never SVG text.
- [**Shot**](?path=/docs/components-media-shot--docs): The one frame for every product image. Transparent images sit on the canvas as a single frame, never a frame inside a frame.
- [**Plate**](?path=/docs/components-graphics-plate--docs): An illustrative SVG diagram, at most one per case: traffic, tokens, portal or care.
- [**Accordion**](?path=/docs/components-content-accordion--docs): Disclosure rows on native details. A title and one-line summary when closed, labelled panels when open. Used for the AI workflow on the home page.
- [**Card**](?path=/docs/components-layout-card--docs): A surface: one tone off the page, a hairline and no shadow. Slot in a kicker, figure, label and note. Used for the AI-impact tiles on the home page.
- [**Results table**](?path=/docs/components-data-results-table--docs): The reported results of a case, label on the left and the figure on the right, with a soft row highlight on hover.
- [**Comparison table**](?path=/docs/components-data-comparison-table--docs): Before and after figures, with two bars drawn to the same scale.
- [**Availability**](?path=/docs/components-content-availability--docs): The line that says Mick is open to new projects ("Open to new projects in 2027"). The year ticks over like an odometer the first time it scrolls into view. The text comes from `availability` in `src/data/site.ts`.
## Patterns

Blocks of the site built from the components above. Each one is the same file the site renders, so a change shows here and on the page.

- [**Site header**](?path=/docs/patterns-site-header--docs): The sticky masthead with the mark, section links, theme toggle and the contact button.
- [**Site footer**](?path=/docs/patterns-site-footer--docs): The closing question, contact routes and the record of cases with their headline figures.
- [**Case card**](?path=/docs/patterns-case-card--docs): One row of the selected-work list, with a Shot or an animated demo.
- [**Impact band**](?path=/docs/patterns-impact-band--docs): The results of a case as a bento grid, with the headline result large.
- [**Case chapter**](?path=/docs/patterns-case-chapter--docs): One numbered chapter of a case page, with its blocks.

## Run it

Node 22. From the `Core/` folder:

```bash
npm run storybook        # dev server on port 6006
npm run build-storybook  # static build into storybook-static/
npm run build            # the site build, the only automated check
```

Every command and check is listed on the [Toolkit](?path=/docs/guides-toolkit--docs) page.

Stories use the community Astro framework (`@storybook-astro/framework`), because Storybook has no official Astro support.
