# What's next

What is not done yet, and what to know before relying on it. Each item says why it matters.

## Documentation

- **Portrait and Blueprint have no usage note.** `docs/DESIGN.md` does not say when to use them, so their stories show only what they render. Without that note, a newcomer cannot tell where each one belongs.
- **Other tile surfaces still repeat the card recipe.** The home "why me" bento tiles, the case-study cards and the stat tiles each carry their own copy of the hairline, 12px corner and tinted surface. Folding them into Card is the next clean-up.
- **Page scripts do not run in Storybook.** The Patterns and Prototypes show the real header, footer, home page and case pages, but the counting figures, the before-and-after slider, the table-of-contents highlight, the copy-email button and the theme toggle are page scripts, so they run on the site only. Check those on the live page.
- **Some stories have no usage line.** Portrait, Blueprint, Availability, Plate, Results table, Comparison table and the Button states demo have no one-line note on when to use each story. The notes need a source (`docs/DESIGN.md` or the owner), so they are not filled in.
- **Three components have no story.** Analytics and ScrollChrome are scripts with nothing to see. Replay is the replay button inside Shot, the Button states demo, the demos and the home page, so it shows up in those stories.
- **Story content is real case-study copy.** Glyph, Plate, Shot and ButtonStates read from `src/data/work.ts`, and Button uses the booking link and label from `src/data/site.ts`. The Foundations sample words and the Availability, Portrait and Blueprint stories are not case copy.

## Checks

- **Case cards fail colour contrast by choice.** At rest every case card on the home page sits at 40% strength, so its small text is below the AA minimum until a card leads or is hovered (owner choice, 2026-10-22). `npm run check:a11y` lists it as accepted, not as passed. Touch screens show full strength.

## Design tokens and Figma

- **Primitive colours are named only in Storybook.** The Primitives page names each colour by family and step (`neutral-300`), but `global.css` still points the semantic tokens at raw hex values. Defining those names in the CSS would make the primitive tier real.
- **Shadows are not tokens.** The consent banner writes its own shadow. If a second floating surface ever appears, define an elevation token first.
- **Tokens are CSS only.** There is no JSON source that maps to Figma variables.
- **Sync status is not built.** It would check that each component in code matches its Figma component. It needs a Figma library of these components first. When it exists it also becomes a check on the [Toolkit](?path=/docs/guides-toolkit--docs) page.
